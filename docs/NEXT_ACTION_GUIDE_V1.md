## 1. 先把当前问题讲清楚

现在已有能拟合的150019参数CNN和可运行的训练入口；缺的不是再找一个编码器，而是能放心使用的新监督和能证明迁移的新评估目标。因此下一项是S1-1：把候选记录的“来自哪次实验、什么构建体、与旧数据什么关系”查清楚。不要把查文献、核对标签和分配split合成一个自动布尔值。

当前固定CNN＋balanced BCE；伙伴竞争v2六次对照未过门槛，已经停止。RWKV/Transformer/EGNN编码器扫描也已止损；J门控关闭。全池1D预训练、辅助A/B/C、新盲测均没有开始。旧8条test已揭盲，不能再用来选方案。

在项目目录打开以下材料即可，不需要先训练或查询网络：


本地逐条文献候选在：

```text
data/manifests/data_first_clean_release_crossref_review_v2.jsonl
```

这些是已有、Git忽略的本地台账。CIF元数据、关系明细的实际位置从对应审计脚本/清单核对，不能猜一个目录就当来源。聚合报告说明哪些缺口存在，逐条台账才用来定位entry/链/候选论文。

注意几个计数不混用：10个缺主研究键的关联结构entry映射到8条记录；133/141表示所有关联entry具有研究键的记录数，不是133条已证明独立；67条是另一版本clean_release相对joint没有精确同序列的候选，不等于joint隔离的70条。它们不能相加成为新训练数量。

已有审计工具多会拒绝覆盖原产物。不要重跑RCSB/Crossref查询来“看看是否变好”，不要删除旧报告以绕过拒绝覆盖。后续确有新证据时用新版本并保存新增来源收据。

## 3. 先做一个小批次的文献人工核对

建议先选已有题名/作者候选的一小批记录，按固定记录顺序审核，记录选择规则，不按模型分数挑样本。另取没有可核实候选的条目，确认如何记录unknown；不为填满字段硬认DOI。批次大小只是工作安排，不是统计样本量或准入门槛。

每条记录按下面顺序查看：

1. 从本地entry主引文题名、作者和已有候选DOI定位原始论文；先确认候选指的是论文，不是PDB entry本身的结构DOI。
2. 对照论文正文/补充材料是否列出相应结构entry、RNA名称、链及实验构建体。题名相同只能作为线索；已发现的5个候选DOI尚未通过这一步。
3. 确认实际实验方法和结构是否覆盖目标链；保留所依据页码、图表、补充表或明确段落。若全文/补充材料不可获得，登记缺口，不假装完成。
4. 保存获取URL、获取时间、原文件SHA256和核对位置。已有原文件不重复下载；新材料放独立版本目录，原始文件不覆盖。
5. 仅在核实后，将研究关系记为“文献已确认”。这还没有证明构建体或家族独立。

不用先把8条全部解决才研究其他证据：文献已经可核实的候选也可以进入下一步构建体审核；但每条缺什么仍须明确。

## 4. 再查构建体：两个名字是否其实是同一个母本

对每条记录，从论文methods、序列表、补充材料及已有实体注释中找：天然母本/来源片段、起止位置、工程突变、插入删除、两端接头/标签、链和复合物背景。把论文序列与当前完整序列逐位映射；保留坐标链编号与序列编号的对应关系。

需要回答：它是不是现有train/validation/test的突变体、截短体或同一结构的重复测定？如果是，把它们连成同一构建体关系；序列不完全相同不能当作独立。

母本查不到时写unknown。没有通用数据库字段不是必须放弃这条数据，但必须有可追溯的替代文献证据和明确审核规则；仅有“synthetic”“RNA fragment”或不同PDB编号不够。复合物中得到的配对标签还需保留蛋白/多链背景，不能直接说成游离RNA的序列唯一结构。

## 5. 接着查同源与历史暴露：决定它能用在哪里

使用已有RNA3DB组件、可核实的家族/比对和冻结局部相似性关系，结合原研究、构建体、重复entry，建立明确关系。现有筛查identity≥0.8且覆盖较短序列≥0.8，只能发现规定范围内关系；没命中不等于无远缘同源。缺失的组件不是“新家族”。

这里的审核目标是在预先声明范围内建立有证据的隔离，不能要求证明宇宙中绝无未知亲缘，也不能把没有证据当成独立。新增论文证据若把两个旧split连起来，先登记桥接冲突，在新版本设计中处理，不手改旧冻结划分。

| 审核结果 | 下一步去向 |
| --- | --- |
| 与现有train关联且证据/标签合格 | 可列为新训练版本候选；不重复计数，不自动写回当前train |
| 与现有validation/test或历史已暴露评估组关联 | 不充当新独立盲测；对当前训练仍按冻结隔离门禁处理，不能为扩量挪入 |
| 未知构建体/同源/研究关系 | 继续隔离，写清缺哪份证据；不是质量差或模型伪数据的同义词 |
| 具有预声明范围内的独立证据且质量/标签审核通过 | 可列为新的开发/测试候选组，先固定角色与访问规则，尚不看模型表现 |
| 与现有同序列但mask/pairs不同 | 进入标签分歧复核；不选对模型最有利的标签，也不静默覆盖 |

“可列为候选”不等于准入完成；关系、标签范围、分组及版本检查都通过后才发布新清单。没有新独立组时如实保留无新盲测，允许做明确标注的工程开发，但不宣称泛化突破。

## 6. 把审核写成可复查的小表

建议新工作文件放`data/reports/manual_evidence_review_v1/`（已有reports忽略规则覆盖），独立于原台账。下面是建议字段，不是已生成或已通过审核的真实记录：

```text
record_id / sequence_sha256 / source_pool_version
entry_id / chain_id / entity_id
paper_candidate_doi / confirmed_primary_study_key
paper_url / retrieved_at / source_file_sha256 / evidence_page_or_table
parent_construct / sequence_range / edits_and_adapters / mapping_evidence
family_or_component / evidence_source_and_version
relations_to_current_and_historical_splits / relation_evidence
label_scope / unresolved_conflicts / remaining_unknowns
citation_status / construct_status / homology_status / label_status
proposed_role / decision_reason / review_date
```

子项可用verified / unresolved / conflict / not_applicable（后者须有理由）；总体先用review_pending或retain_quarantine，不以“查到引用”直接置training_allowed=true。引用字段和人工结论都保存证据定位；仅复制DOI不算审核。

例如：某记录论文与链已确认，但母本未知，则结论是“citation verified；construct unresolved；继续隔离”，而不是“全部失败”，也不是“可训练”。

每批结束交付：审核条数、补齐了哪些关系、仍缺什么、冲突数、候选去向及计数。逐记录内容留本地；仓库提交规则、聚合计数和哈希。更新台账、commit、push，再做下一批。当前指南没有创建或放行任何真实审核记录。

## 7. 证据补齐后，才生成新数据版本

这一步须在上述材料确有新增可核实关系后执行，当前尚未执行：

1. 新建关系/准入版本，记录旧版本与新增证据差异，保留所有原数据/原划分。
2. 将新旧2D、1D、profile、辅助及历史评估关系一起审核，按预声明关系合并隔离组；不能只对新候选相互去重。
3. 分开训练增量和新评估候选；按组划分，报告组数、长度、实验背景与标签覆盖。评估标准不得根据模型在新测试的表现修改。
4. 对来源、序列映射、正/负/未知标签、链间失去伙伴端点、padding、重复和跨split连接逐项验证。保持模型预测/补全标签排除政策。
5. 生成新的manifest、文件SHA、逐条排除原因和验证摘要。重用旧split时先证明没有新增连接冲突；发现冲突先停止，不在原版上打补丁。

这不要求固定比例或固定新样本总数；证据和独立组覆盖不足时，发布审核结果即可，不为凑训练/测试数字降低门槛。

## 8. 若辅助2D通过审核，再做S3链路验收

当前S3未开始。比较分析辅助只在有原文/比对/映射与监督范围证据时准入，不自动视为实验金标准。现有端点mask不能表达“只有若干正边，其余未知”，需独立配对级mask；positive-only在首轮二分类协议中仍不能直接放行。

先写有意义的契约检查：未知边改变不影响损失；padding不改变有效预测；无有效候选记录/空组从预定义准入与宏平均分母正确处理；可靠负标签但无正边的记录不误删；模型不能用真值mask避开未知端点的解码竞争。

然后做每条件一个种子、至多5更新的独立冒烟：A实验5步；B实验2步→重建AdamW→实验3步；C辅助2步→重建AdamW→实验3步。B/C后段相同采样，核对权重保留/优化器重置、日志、mask和检查点重载。冒烟不看新test，不用于性能结论，不接续其权重正式训练。没有辅助准入时不要用伪样本强行跑C。

## 9. 通过后才冻结A/B/C，回答数据有没有帮助

| 条件 | 流程 | 回答的问题 |
| --- | --- | --- |
| A | 实验监督U步 | 原预算工程参照 |
| B | 实验Ua步→优化器重置→实验Uf步 | 多训练相同阶段/总更新是否本来就有帮助 |
| C | 辅助Ua步→优化器重置→实验Uf步 | 辅助监督是否比B更有帮助 |

正式前填整数U/Ua/Uf、固定CNN/BCE、种子42/43/44、数据SHA、采样、最终检查点规则、最小实用提升delta和严重退步门槛。B/C后段实验采样对齐；同更新不冒充同FLOPs。主比较C-B，不是只看C-A。

三条件×三种子共9次；不要用普通CLI随意运行替代尚未实现/冻结的A/B/C runner。先提交推送协议，再执行；报告训练拟合、开发逐RNA及组宏F1、全种子/逐组差值、资源和重载。过门槛才考虑独立test；没有新test就只作开发决定。未达标归档停止，不增加种子或另调lambda追阳性。详见[执行细则第6节](DATA_FIRST_EXECUTION_V1.md)。
