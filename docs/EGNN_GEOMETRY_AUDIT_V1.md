# EGNN几何输入审计

用户指出先前验证差异混合了训练拟合差异，因此不能作为架构泛化优劣证据。本项先检查几何输入，再进入固定lr扫描。原模型实现和旧检查点未改动。

读取原seed42最终EGNN-seed检查点，用真实训练记录2DR8_A/2B57_A/8IDY_A（长度33/65/120）组成变长batch，实际张量如下，两层均一致：

| 张量 | 形状 |
| --- | --- |
| 节点特征 | [3,120,64] |
| 坐标输入/输出 | [3,120,3] |
| 平方距离 | [3,120,120,1] |
| 边网络输入 | [3,120,120,130] |
| 有效边掩码 | [3,120,120] |
| 坐标更新系数 | [3,120,120,1] |

边输入的第128列（零基）逐位等于从本层坐标计算的平方距离；第129列为相对序列间隔。有效边数为1056/4160/14280，分别等于N(N−1)。Padding坐标、层输出坐标及特征为0；padding涉及的距离本身不必为0，但消息和聚合通过有效边掩码屏蔽。逐条运行与batch有效区域最大logit差9.54e−7，层坐标也一致，没有错位或padding污染证据。

两层最大坐标更新约0.02972、0.02836（位置种子单位，不是nm）。分类输出反传时所有坐标模块参数有非零有限梯度；只将坐标更新系数强制为0、保留边距离输入，logit最大改变0.07372。说明坐标路径确实参与预测，未被旁路。

重要边界：坐标是(cos i,sin i,i/128)的位置种子，不是实验RNA几何。没有丢失坐标/距离张量的问题，但输入并不包含真实分子几何；这是序列→2D公平信息范围的设定，而非EGNN最适任务。不能为改善分数注入实验终态坐标，否则会改变任务并造成结构信息泄漏。

审计没有发现需要修复的上述几何接口错误，保持模型不变进入用户限定的lr扫描。结果与源/检查点SHA见data/manifests/egnn_geometry_audit_v1.json；脚本audit_egnn_geometry.py。该受检实例和单元测试不是对所有潜在实现问题的完备证明。
