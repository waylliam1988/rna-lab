## 1. 目标与当前决策

近期目标：在可追溯、无已知跨集合泄漏的条件下，验证审核后的辅助监督能否提升仅输入序列的2D配对预测。优先增加独立证据覆盖，再研究架构机制。

固定约150k参数的CNN比较版作为工程参照：`SequencePairModel(kind=cnn,width=113,hidden=64,depth=2)`。当前生产入口已默认使用此版CNN；早期`PairBaseline`为显式回退，历史训练F1和资源数字不得混用。保留现有权重和原实验记录，不覆盖旧数据。

主线：冻结基线 → 联合证据/隔离审计 → 辅助配对池试点 → 新协议下的数据对照 → 独立评估 → 数据扩充或机制研究。

近期不重开编码器调优、不启用未隔离1D预训练、不接回能量驱动J门控。Ghost、RWKV、分步更新和物理接口保留，后续按进入条件单独研究。

## 3. 阶段0：冻结工程参照与实验台账

### 任务

1. 登记CNN源码版本、模型构造参数、配对头、损失、掩码、解码阈值及原检查点SHA256。
2. 登记原训练/开发数据指纹、种子、优化器和预算；记录开发集已被多轮查看的事实。
3. 明确新数据实验采用重新训练还是接续训练。正式对照统一初始化规则，不混用旧权重与随机初始化来归因数据收益。
4. 将旧测试标记为历史结果集；历史与新增样本的连接关系仍须审计。
5. 核对数据政策和文档中的旧计数，生成版本对应表；不静默改写历史清单。

### 交付与验收

- 交付：基线冻结清单、数据版本对应表、实验登记模板。
- 验收：可以明确重建同一模型；每项历史数字能对应具体数据与检查点。
- 停止条件：发现指纹或版本无法对齐时，先解决审计，不开始新性能比较。

## 4. 阶段1：先确定独立评估边界

### 任务

1. 汇总现有金标准、待审实验记录和候选辅助来源的元数据；优先使用已有本地材料，不默认启动大规模下载。
2. 建立关系清单：精确序列、序列相似性、已知家族/更高层同源关系、原始研究、母本/突变体、构建体、重复结构、链及实验背景。未知关系单独登记。
3. 分别声明评估问题：已见家族中的新目标，还是未见家族/同源组的迁移。二者不混成单一泛化结论；序列相似性阈值不能替代全部同源审计。
4. 优先寻找新增独立研究与家族作为测试候选。新测试不得用于训练、选择配置或反复查看指标；与已用于开发的目标存在未解决连接时，不称其为新独立证据。
5. 为新增监督保留独立开发组。现有10条开发集保留用途记录，不把它重新包装为盲测。
6. 在任何辅助训练之前，排除开发/测试及其规定范围内的同源、研究和构建体连接；后续新增来源也必须重新检查。

### 交付与验收

- 交付：联合关系表、隔离清单、样本级去向与原因、新评估候选说明。
- 验收：每条训练记录有去向证据；未知关联不能默认无关联；不能靠拆分同一研究/家族增加组数。
- 新独立组不足：允许继续工程与开发研究，明确没有新盲测，不强行按固定比例切出名义测试集。
- 评估边界先确定；具体样本和标签可由审计流程处理，但不查看候选模型在新测试上的表现来调整边界。

## 5. 阶段2：扩充分别管理的实验池与辅助池

分开管理不表示统计独立；两池与1D、开发/测试之间仍需联合去重和关系隔离。

### 2A. 直接实验配对池

- 优先复核已有隔离记录中的独立注释缺失、工具定义分歧、编号映射和版本差异；以排除原因分层安排工作。
- 分歧未解决的位置遮罩或继续隔离，不为了数量将整条记录改成确定标签。
- 保留复合物、链间作用、小分子/离子及其他可得条件；明确哪些条件可在推理时提供。无法支持sequence-only解释的样本分层报告或隔离。
- NMR、修饰碱基、非经典配对和链间任务采用单独质量协议，不能悄悄扩展当前AU/GC/GU单伙伴任务。

### 2B. 比较分析辅助配对池

先选择一批能够完整追溯的来源做试点；不按数据库名称批量放行，不预设必须达到的数量。

| 必需信息 | 准入要求 |
| --- | --- |
| 来源收据 | 原条目、URL、下载时间、原始文件SHA256、文献与版本 |
| 标签形成方式 | 区分直接实验、比较分析、模型预测、模型补全和未知；后两类及未知不放行 |
| 比对映射 | 保存比对位置到序列位置的映射，核对插入、缺失、端点和编号 |
| 支持范围 | 标记共识边、可用的共变/实验支持及不确定位置；不声称每条分子独立实测 |
| 隔离证据 | 家族、同源组、原研究、构建体关系以及与评估集的排除检查 |
| 质量决定 | 通过/隔离/排除、原因码、审核版本；原始文件不可覆盖 |

共变缺失不自动等于结构错误，共变存在也不自动证明全部边正确。部分配对证据不意味着其余所有位置都已证实未配对；只有标签定义支持的正负位置进入损失。

### 交付与验收

- 交付：版本化辅助记录、证据台账、映射审计、排除统计、与实验金标准分开的目录和清单。
- 验收：每条放行记录通过来源、质量、映射及隔离门禁；无法溯源的记录仍隔离。
- 统计同时给出序列数、同源/研究组数、长度分布、有效监督端点/配对数、标签覆盖率和背景。不能仅用序列数宣称多样性增长。
- 试点无法形成可靠监督：输出可行性与排除原因报告，暂停扩大该来源；不降低证据门槛。
- 首批最多20条为审核流程试点，是否进入正式比较须依据独立组覆盖和有效正负监督量另行判断；不以候选审核数量替代训练可行性验收。

## 6. 阶段3：辅助数据入口与链路验证

### 任务

1. 在独立辅助入口支持比较分析标签，不放宽现有实验金标准门禁；默认路径不自动切换。
2. 为每条标签保存类型、监督掩码和来源，日志分别统计金标准与辅助样本；unknown不等于0。
3. 处理去重、家族不平衡和重复构建体。任何分层抽样或损失权重在协议中明确，不让少数大族重复样本无意主导训练。
4. 先做少量已放行训练样本的冒烟运行，检查加载、损失、梯度、掩码和检查点重载，不访问新测试。
5. 必要契约检查覆盖：拒绝未放行记录、拒绝评估近亲、映射边界、单伙伴/对称性、未知端点、样本间状态重置和重载一致性。
6. 实现新评价准入规则：推理前排除无有效候选监督的RNA，报告排除原因及组级分母；保留可靠负标签但无正边的样本。当前`evaluate`尚未实现该排除，不改写历史指标定义。
7. 冒烟明确走完短阶段：B为实验2+3更新，C为辅助2+实验3更新，中间均重建优化器，核对相同后段采样和独立重载；不接续冒烟状态启动正式运行。

### 交付与验收

- 交付：独立数据入口、契约检查、仅使用训练样本的链路报告。
- 验收：能够追踪每个训练批次的数据来源；拒绝路径可验证；无测试加载；检查点复算一致。
- 技术链路失败先修复；不把失败运行记为架构低分，也不进入正式效果比较。

## 7. 阶段4：冻结第一轮数据实验协议

核心问题：辅助配对监督是否比相同模型、相同总更新预算的仅实验训练更有帮助？

本轮A/B/C统一使用现有带掩码、逐RNA正负类平衡的BCE，不叠加伙伴竞争损失或更换MSE。损失改进另列阶段6D，固定数据后单独对照，避免把数据与损失收益混在一起。

| 条件 | 训练流程 | 用途 |
| --- | --- | --- |
| A | 仅实验训练，基准预算U | 实验监督参照 |
| B | 仅实验训练，预算Ua+Uf | 控制辅助阶段增加的训练更新 |
| C | 辅助训练Ua，随后实验微调Uf | 检验分阶段辅助监督 |

U、Ua、Uf必须在正式运行前写成具体数字。B/C总优化器更新数和batch规则匹配，记录有效碱基/配对数、耗时和显存；变长样本下相同更新不等于相同FLOPs或输入曝光。不要把更新预算对照写成精确计算量匹配。

### 必须预声明的项目

- 相同的CNN结构、任务范围、损失定义、解码器及初始化规则；建议先沿用三个种子42/43/44，并按种子配对比较。
- 基线超参数与允许的小范围开发搜索；若无搜索则明确固定。B/C获得相同的选择机会，不能只为C额外调优。
- 辅助阶段和微调阶段的优化器状态是否重置、学习率计划、样本采样方式及检查点选择规则。B使用对应的阶段边界，以免重置本身成为未控制因素。
- 主比较C对B；A提供原预算参照。辅助训练后微调的收益，不与辅助数据独立信息量、训练曝光量等所有机制混为一谈。
- 开发主指标建议为实验开发集按隔离组宏平均配对F1；同时报告逐RNA宏F1、Precision、Recall、训练拟合、全种子和逐组差异。
- 分层报告长度、配对跨度、交叉边、实验背景、标签覆盖及家族。监督掩码内结果不能解释为全结构准确率。
- 记录分数可靠性或校准诊断；未经校准的输出仍称分数。阈值/校准参数只能用开发集确定。
- 固定数据/源码/配置指纹、失败处理、最大运行数、停止条件和独立重载要求。

### 开发推进规则

在实际组数确认后、训练前冻结一个工程决策规则。建议至少要求C对B三个种子组宏F1均改善、多数组改善、平均绝对提升达到预声明最小实用幅度δ，并报告最大退步组及其规模。δ由项目用途预先确定，不能看结果再设。

该规则仅用于决定是否值得继续，不是统计显著性检验。组数过少时不作普遍结论；不要把同一组的多个种子当独立生物学样本。若报告不确定性，说明组级重采样方法及小组数限制。

本轮只运行冻结的A/B/C及预声明种子；失败、阴性和不一致结果均保留。不得通过增加种子、改阈值或继续搜索直到阳性。

## 8. 阶段5：独立评估与结果分流

仅在开发选择结束、模型/解码/预算全部冻结后，对预声明方案进行一次新独立测试评估；保存全部种子，不挑测试最优种子。新测试一旦用于选择或解释后续改动，就不再是该后续改动的未见测试。

| 结果 | 下一步 |
| --- | --- |
| C对B在开发中较一致改善，独立测试也有支持 | 固定成功版本，再扩充新的独立证据覆盖；不直接宣称广泛跨家族泛化 |
| C只超过A，未超过B | 不能归因辅助监督有独立增益；增加训练预算是竞争解释 |
| 平均改善但少数组严重退步 | 分析背景/覆盖/家族差异；下一假设另立开发协议，不用测试选子集 |
| 训练改善，开发/测试无收益 | 检查标签差异、负迁移和采样偏置；不立即放大网络 |
| 没有新独立测试 | 仅报告开发证据，继续扩充评估覆盖，不升级为盲测结论 |
| 辅助标签准入困难或预算内无收益 | 停止该轮扩大，保留阴性结果；考虑独立的探测多任务可行性研究 |

## 9. 阶段6：后续分支的进入条件

### 6A. 实测反应性多任务

前提：完成原研究、母本/构建体和同源隔离；明确试剂、条件、误差、重复及缺失处理。RMDB等完整池不自动获准训练。

建立独立反应性预测或观测似然目标；若共享编码器，分别记录辅助输入条件和sequence-only配对任务的推理输入。不得让评估样本的实测反应性暗中进入sequence-only预测。

对照至少包含固定CNN、预算匹配CNN、多任务CNN；先验证辅助任务可学习，再检验配对收益。收益不成立允许停止。暂不同时叠加比较辅助池、反应性任务与新架构，以免无法归因。

### 6B. 上下文、分步更新、Ghost与RWKV

前提：数据与评估版本已固定，存在可复核的比较基础和明确待解决问题。当前编码器扫描止损继续生效，重开需要新的、有边界的实验协议。

- 长上下文：先检查配对跨度分层是否显示具体瓶颈，再比较受控的上下文改动。CNN感受野17不意味着无法给远距离配对打分，也不证明已经具备充分全局结构理解。
- 分步更新：与单步及预算对照比较，允许增加/撤销配对；固定推理步数或可实现的停止规则，不用标签选择最佳中间态。
- Ghost：与相同输入的无记忆局部网络和普通迭代比较。
- RWKV：在已固定Ghost/其他基础上单独验证记忆增量，区分序列编码记忆与结构迭代记忆；不跨不相关RNA携带状态。
- 对每项记录参数、训练更新、输入曝光和资源；不因参数接近就称计算公平。充分拟合是诊断证据，不是普遍架构优越性的充分条件。

### 6C. 可选3D精修

保留现有接口和结果，不将其作为当前数据主线的必经阶段。启动新的结构精修任务前，需明确局部状态、坐标/方向与动量语义、旋转平移一致性和动作执行约束。

分开评估：已知状态的宏观预测、实验结构扰动恢复、模型自身序列初始化后的精修。按同初始候选、同展开预算比较不精修/纯物理/无记忆修正/Ghost，最后才加RWKV。

必须检查配对、结构距离、局部几何、碰撞、闭环稳定性和候选选择效果；能量降低或宏观预测更准不等于结构正确。实验终态不得用于生成sequence-only评估的初始坐标、J或动态接触。

当前J及物理定义冻结，预测配对先验接入另作因素实验；不恢复能量驱动J门控。模拟轨迹仍标记辅助数据，不称真实折叠轨迹；计算步不称物理时间，不用终态前缀裁剪冒充共转录标签。

### 6D. 配对损失改进：BCE与伙伴竞争

前提：第一轮数据对照完成并归档，训练/开发数据、配对级正负未知语义和CNN参照已冻结。若辅助来源不可行，在归档其停止原因后，也可用已放行的固定实验数据另立协议；不能在未完成隔离时启动。

首个候选是`L = L_BCE + lambda * L_competition`。对已知正边i–j，比较真实伙伴logit与共享端点的可靠负候选：`L_i = log(1 + sum_{k in N_i} exp(z_ik - z_ij))`，对j端同样计算。未知边不进入N_i；正边或可靠负候选不足时跳过竞争项，不伪造监督。按端点、RNA逐级平均，具体稳定实现与契约检查见[执行细则第8节](DATA_FIRST_EXECUTION_V1.md#8-独立的配对损失对照待实现)。该候选不保证全局匹配或结构合法，也没有本项目增益证据。

正式对照固定同一CNN、数据清单、初始化、训练流程、采样顺序、更新预算和解码，仅比较现有BCE与BCE＋伙伴竞争；不同时更换数据池或加入新架构。种子42/43/44，固定一个预声明lambda，首轮2条件×3种子，共6次；lambda、预算、最小实用提升和严重退步阈值须运行前另行冻结，不把候选公式当成已冻结运行协议。2026-10-28已按v2冻结并执行；因v1首个seed在验证评价出现批次维度技术失败，v1保留失败且未补跑，修复后v2六次均从头运行。v2 gate不通过，见[结果报告](DATA_FIRST_LOSS_RESULTS_V2.md)；伙伴竞争候选停止合入，默认继续BCE。

主指标仍为实验开发组宏F1，保留逐RNA、逐组、全种子Precision/Recall及最大退步。辅助诊断包括解码前多伙伴高分端点比例、竞争项覆盖率与正负候选数；诊断改善不能替代F1收益。无一致开发收益或严重退步时停止，不追加lambda/种子直到阳性；无新独立测试只报告开发证据。阶段5已使用的测试不再作为该新损失的未见测试。

后续候选优先级：伙伴分类交叉熵（显式“不配对”类别、未知与对称性另行设计）→有具体误差证据再考虑soft Dice/F1或Focal。暂不以MSE替代配对BCE，不在现有正负平衡上直接叠加大pos_weight。原理参考：[UFold的加权交叉熵](https://pmc.ncbi.nlm.nih.gov/articles/PMC8860580/)、[伙伴多分类研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC12008525/)、[BCE权重定义](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.loss.BCEWithLogitsLoss.html)；这些资料不证明本项目候选组合有效。

交付：独立损失协议、掩码/梯度契约检查、6次运行及重载报告、逐组差值和继续/停止结论。共享BCE与竞争项函数及契约检查已实现；v2对照、重载、汇总均完成，开发gate不通过。竞争项保留为未合入候选，未形成可选训练配置或默认启用；balanced BCE仍为默认。具体限制和指纹见[结果报告](DATA_FIRST_LOSS_RESULTS_V2.md)及进度台账S6-L。

## 10. 执行顺序与最小交付

不承诺固定日历周期，主要依赖证据可得性和独立组覆盖。逐阶段验收，不因达到日期而跳过门禁。
